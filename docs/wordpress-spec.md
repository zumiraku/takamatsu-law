## 2. 投稿タイプとタクソノミー

### 2.1 `column`（コラム）

固定ページ・お知らせとは分けた独立の投稿タイプにします。記事が増えても管理画面が
混ざらず、分野ごとの一覧・並べ替えが自由になります。

- スラッグ: `column`、アーカイブ有効、`has_archive: 'column'`
- タクソノミー: `column_category`（階層あり／単一選択の運用）、`column_tag`（自由入力）
- 対応するカテゴリー（初期値）

| 表示名         | スラッグ         |
| -------------- | ---------------- |
| 交通事故       | `kotsu-jiko`     |
| 相続           | `souzoku`        |
| 離婚・男女問題 | `rikon`          |
| 投資被害       | `toshi-higai`    |
| 消費者被害     | `shohisha-higai` |
| 雑感・その他   | `zakkan`         |

#### カスタムフィールド

| フィールド              | 型                   | 用途                                                        | 必須 |
| ----------------------- | -------------------- | ----------------------------------------------------------- | ---- |
| `excerpt`（標準の抜粋） | テキスト             | 一覧の説明文、meta description、OGP                         | ○    |
| `summary`               | 繰り返し（3行程度）  | 記事冒頭の「この記事の要点」。note の要約にもそのまま使える | ○    |
| `note_url`              | URL                  | note 側の記事 URL。空なら記事下の note 導線は出ない         | —    |
| `note_kind`             | 選択（要約版／有料） | 記事下の文言を切り替える                                    | —    |
| `note_price`            | 数値                 | 有料記事の価格。表示に使う                                  | —    |
| `old_paths`             | 繰り返し（テキスト） | 現行サイトの URL。301 の生成に使う                          | —    |
| `updated_at`            | 日付                 | 加筆日。構造化データの `dateModified` に入る                | —    |

本文は標準のブロックエディタを使い、**見出し2（h2）・段落・箇条書き・引用**のみを
使う運用とします。試作環境の `Block` 型がそのまま対応します。目次・構造化データ・
読了目安時間は、この見出し構造から自動生成されます（執筆時に目次を作る必要はありません）。

### 2.2 `lawyer`（弁護士）

顔写真は使わない方針のため、氏名の一文字からシンボルマークを生成して表示します。

| フィールド               | 型                                               |
| ------------------------ | ------------------------------------------------ |
| `name` / `kana` / `role` | テキスト                                         |
| `mark`                   | テキスト（1文字。省略時は氏名の先頭文字）        |
| `fields`                 | 繰り返し（取扱分野）                             |
| `career`                 | 繰り返し（経歴）                                 |
| `positions`              | 繰り返し（役職等）                               |
| `affiliations`           | 繰り返し（所属・資格）                           |
| `cases`                  | 繰り返しグループ（`court` / `side` / `summary`） |
| `message`                | テキストエリア                                   |
| `cooperating`            | 真偽（協力弁護士）                               |

弁護士が増えた場合は、この投稿を1件追加するだけで一覧に整形して並びます。
レイアウトの発注は不要です。

表示は「現行より簡略化」のご要望に沿って、最初に見えるのは**取扱分野と経歴**まで。
`positions` / `affiliations` / `cases` は件数付きの折りたたみに入れ、開いた人だけが
読む形にしています。実績を削らずに、初見の情報量だけを減らすためです。
折りたたみは JavaScript を使わない `details` 要素なので、読み上げソフトでも
印刷でも開けます。

### 2.3 `practice`（取扱業務）

こちらも「現行より簡略化」に合わせ、分野ごとの装飾写真は使いません。
一般的な室内写真は「交通事故」と「相続」の違いを何も語らず、読む妨げと
通信量になるだけのためです。番号とロゴのダイヤで区切る構成にしています。

| フィールド       | 型                         |
| ---------------- | -------------------------- |
| `group`          | 選択（個人の方／企業の方） |
| `title` / `lead` | テキスト                   |
| `items`          | 繰り返し（取扱項目）       |
| `old_paths`      | 繰り返し（301 用）         |

### 2.4 `news`（お知らせ）／ `faq`（よくあるご質問）

- `news`: タイトル・日付・本文のみ。コラムとは分けて、休業案内や料金改定を置きます。
- `faq`: `question` / `answer` / `group`（ご相談の前に／費用について／ご相談の当日）。
  `answer` は構造化データ（FAQPage）にもそのまま使うため、リンクを含まない
  一文完結の文章で入力します。

## 3. 事務所で更新できる範囲

- コラム、お知らせ、よくあるご質問の追加・編集・公開日変更
- 弁護士の追加・経歴の修正・関与判例の追加
- 取扱業務の文言と項目
- 固定ページ（トップの各セクション文言を含む）の本文
- 弁護士費用の表（表組みは繰り返しフィールドで入力）
- note のアカウント URL と公開／非公開の切り替え（設定画面1か所）

デザインの崩れる操作ができないよう、レイアウトに関わる指定は管理画面に出しません。

## 4. 画面まわりの実装メモ

- 本文は 16.5〜17px、行間 2.05。60代・70代の閲覧を前提にした値です。
- 主要な操作要素は 44px 以上のタップ領域を確保しています。
- ヘッダーのナビゲーションは、項目が入りきらない幅になった時点で自動的に
  ハンバーガーメニューへ切り替わります（固定のブレークポイントではありません）。
- `prefers-reduced-motion` を尊重し、動きを抑える設定の端末ではアニメーションを止めます。
- 掲載写真はすべて仮のものです。事務所さんからお預かりする写真に差し替える前提で、
  代替テキスト（alt）でも「当事務所の相談室」等と名乗らせていません。実際の場所で
  ないものを、そうだと書かないためです。
- SNS 共有時のカード画像（OGP）はロゴを載せた専用のものを用意しています。写真の
  切り出しだと、共有されても誰の記事か分からないためです。
- ホーム画面に追加したときのアイコンは、ロゴのダイヤ部分を正方形で書き出しています
  （横長のロゴを指定すると潰れます）。

## 5. 表示速度

法律事務所のサイトは、検索から来た方が「重い」と感じた時点で閉じられます。
以下は試作環境で実施済みで、WordPress 版でも同じ方針を引き継ぎます。

| 対象       | 施策                                                                                   | 効果                               |
| ---------- | -------------------------------------------------------------------------------------- | ---------------------------------- |
| 画像       | WebP 化に加えて、幅ちがい（640 / 768 / 1280 / 1920px）を書き出し `srcset` で出し分け   | トップの主画像が携帯で 69KB → 26KB |
| ロゴ       | 全ページに出るため JPEG → WebP（1x / 2x）                                              | 15KB → 5KB                         |
| CSS        | 未使用の UI キットを走査対象から除外                                                   | 106KB → 57KB（gzip 10.5KB）        |
| JavaScript | 使っていないデータ取得ライブラリを撤去、トースト表示はお問い合わせページだけに読み込む | 434KB → 377KB（gzip 116KB）        |
| フォント   | 本文書体は実際に使う 400 のみ読み込む（日本語は1ウェイトが重い）                       | 余分な書体ファイルの取得をなくす   |
| 主画像     | `preload` を `srcset` と揃える                                                         | 携帯で大小2枚を取りに行くのを防ぐ  |

WordPress 版での対応

- 画像は WordPress の `srcset` 自動出力を使い、`add_image_size()` で上表の幅を登録します。
- 主画像（各ページ最上部）だけ `loading="eager"` ＋ `fetchpriority="high"`、
  それ以外は遅延読み込みにします。
- テーマの CSS / JS は必要なページでのみ読み込みます（`wp_enqueue_*` の条件分岐）。
- プラグインは必要最小限に留めます。多くのプラグインは全ページで CSS / JS を
  読み込むため、入れるほど遅くなります。
- 日付は必ずサイトのタイムゾーン（Asia/Tokyo）で出力します。サーバーの
  タイムゾーン任せにすると、環境によって表示が1日ずれます。
