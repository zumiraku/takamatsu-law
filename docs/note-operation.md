# note 運用ルール

将来 note で発信・販売を行うことを前提に、あとから困らない形で設計してあります。
このドキュメントは、その考え方と、実際に開設したときの手順をまとめたものです。

## 1. なぜルールが要るのか

同じ本文を自社サイトと note の両方に載せると、検索エンジンからは
**同一の内容が二か所にある**状態に見えます。その結果、

- どちらを検索結果に出すかの判断が分かれ、評価が分散する
- note 側が優先されると、事務所のドメインに評価が蓄積しない
- 最悪の場合、どちらも上位に出にくくなる

という事態が起こり得ます。note は強いドメインなので、後者は現実的なリスクです。

## 2. 決めごと

| | 掲載する内容 | 正規URL（canonical） |
| --- | --- | --- |
| 当サイトのコラム | 全文 | 当サイトの記事URL |
| note（要約版） | 要点＋導入＋本文への導線 | 当サイトの記事URL |
| note（有料記事） | note 限定の書き下ろし | note の記事URL |

- **全文は必ず当サイト。** note には要約と導線のみ。
- 有料記事は、無料記事の焼き直しにしない。**別に書き下ろす。**
  当サイトには導入と目次だけを置き、続きを note で読んでいただく形にします。
- note の記事末尾には、当サイトの該当記事へのリンクを必ず置きます。

### canonical について

各コラムには当サイトの URL を `<link rel="canonical">` として出力済みです
（`src/routes/column/$slug.tsx`）。note 側でも、記事の設定から
「この記事は他サイトが初出である」旨のリンクを本文に置きます。
note は canonical タグの任意指定に対応していないため、
**要約にとどめる**ことが実質的な重複回避策になります。だからこそルール1が重要です。

## 3. 開設したときの手順（試作環境）

`src/lib/note.ts` を1か所書き換えるだけです。

```ts
export const NOTE = {
  status: "live",                          // "planned" から変更
  accountUrl: "https://note.com/xxxxxxxx", // 事務所のアカウント
  handle: "xxxxxxxx",
  salesEnabled: false,                     // 有料記事を始めたら true
} as const;
```

これで次の場所が同時に有効になります。

- コラム一覧ページ下部の note 導線
- 発信について（`/publishing`）の note 導線
- フッターの `NOTE` リンク
- 構造化データの `sameAs`（事務所の公式アカウントとして検索エンジンに伝わる）

記事ごとの導線は、その記事に `noteRef` を入れたときだけ出ます。

```ts
// 要約版を note に載せた場合
noteRef: { kind: "digest", url: "https://note.com/xxxxxxxx/n/nXXXXXXXX" }

// note 限定の有料記事に誘導する場合
noteRef: { kind: "paid", url: "https://note.com/xxxxxxxx/n/nXXXXXXXX", price: 500 }
```

`url` が空のままなら、記事下には何も表示されません。準備中の記事に
中途半端なリンクが出ることはありません。

WordPress 版では、上記が投稿編集画面の `note_url` / `note_kind` / `note_price`
の3項目と、設定画面の note アカウント欄に対応します。

## 4. 有料化する記事の選び方

勘で決めずに済むよう、記事ごとの反応を計測しています。詳しくは
[seo-migration.md](./seo-migration.md) の「計測設計」を参照してください。

1. まず当サイトで無料公開する
2. `article_view`（開かれた数）と `article_progress`（50% / 90% まで読まれた数）を見る
3. **読了率の高い主題**を選んで、note 限定の書き下ろしにする

「開かれた数」が多い記事は検索での入口として価値があり、
「最後まで読まれた数」が多い記事は深く知りたい読者がいる主題です。
有料化を検討するのは後者です。この2つを分けて取れるようにしてあるのが要点です。

## 5. やらないこと

- 同じ本文を両方に全文掲載する
- note の記事を、当サイトからの唯一の情報発信にする
- 無料で読める記事を、そのまま有料に切り替える
- 事務所のアカウント以外（担当者個人のアカウント等）へ導線を張る
